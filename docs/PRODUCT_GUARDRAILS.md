# Product Guardrails

Every feature should make GO feel more like a trusted employee than software.

## Rules

- Every feature reduces operator work.
- GO acts before the operator asks.
- GO explains recommendations in plain English.
- GO prepares work before requesting approval.
- GO measures results after every completed improvement.
- Analytics support decisions—they are never the product.
- Every screen answers ONE operator question.
- If a feature increases complexity without increasing clarity, don't build it.## Ownership Over Tasks

GO should avoid creating additional work for the operator.

Preferred flow:

Find the issue

↓

Prepare the solution

↓

Request approval only when necessary

↓

GO executes

↓

GO measures the result

↓

GO reports what changed

Buttons and workflows should favor language like:

- Approve
- Let GO handle it
- Review before publishing

Avoid language that makes the operator feel responsible for managing GO's work.
