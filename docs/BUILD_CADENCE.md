# Growth Operator Build Cadence

## Principle
Founder time is scarce. Growth Operator development should optimize founder time the same way the product is intended to optimize operator time.

## Default cadence
Build meaningful vertical slices, not founder-tested micro-patches.

Builder loop:
1. Define the product capability and acceptance criteria.
2. Implement the full vertical slice across the required files/systems.
3. Self-review architecture, evidence boundaries, failure states and UX handoffs.
4. Run or create regression checks wherever the environment permits.
5. Iterate internally before requesting founder testing.
6. Bring Markus back in when founder judgment is genuinely valuable.

Founder loop:
- Product/strategy decisions.
- Access or business context only Markus can provide.
- Testing a materially improved vertical slice against real operators.
- Evaluating whether the experience is understandable, credible, exciting and commercially valuable.

Do not ask Markus to repeatedly test mechanical implementation details that can be validated by the Builder.

## Build sizing
Prefer substantial capability checkpoints over many tiny numbered builds. A build may touch many files and contain large changes when that is the cleanest way to deliver a coherent capability. Avoid a single uncontrolled moonshot when intermediate learning materially reduces risk.

## Optimization rule
Before asking Markus to perform a repetitive step, manually transfer code/files, test a tiny implementation change, or provide information GO should ultimately discover itself, first ask whether the Builder can automate it, batch it, validate it, or eliminate the step.

## Current product sequence
1. Cold-Start Intelligence V1: URL -> business truth -> product families -> traveler intent -> representative demand portfolio -> public evidence -> judgment.
2. Operator Snapshot / Growth Score V2: simple evidence-backed business read, public scenario economics, and clear next action.
3. Public GO Analyzer / company website funnel: a real operator-facing acquisition experience.
4. Mission approval + connected data: replace scenarios with operator economics and prepare execution.
5. Execution + measurement loop: act, measure, attribute, learn, repeat.

## Quality boundary
Speed must not weaken evidence integrity. UNKNOWN never becomes a gap/opportunity/economic loss. Public evidence may create scenarios; connected data creates operator-specific estimates; measured results create attributed impact.
